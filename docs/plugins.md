# Додатки PicoView

PicoView лишається однією програмою в одному файлі. Додатки нічого в цьому не
змінюють: поки поруч із `PicoView.exe` немає теки `plugins`, увесь механізм —
це одна перевірка існування теки на старті, і вона нічого не коштує.

Заміряно: з одним завантаженим додатком холодний старт 250.8 мс проти 246.7 мс
без теки `plugins` (медіана з п'яти запусків). Тобто один DLL — близько 4 мс.

## Звідки вони беруться

Два шляхи, і перший — той, заради якого це робилося.

**З каталогу проєкту.** «Налаштування → Додатки» показує, що публікує проєкт.
Натискаєте «Встановити» — файл завантажується в `%APPDATA%\PicoView\plugins`,
перевіряється й одразу вмикається. Перезапуск потрібен лише щоб зʼявилися нові
**формати файлів**: цей список збирається один раз на старті, свідомо.

Каталог — це `plugins/catalog.json` у цьому ж репозиторії, який програма читає
з `raw.githubusercontent.com`. Адреса вшита в код і не налаштовується: адреса
каталогу, яку можна підмінити налаштуванням, — це відчинені двері.

Завантажити код і запустити його — рівно так серйозно, як звучить. Що тримає
це чесним:

* тільки HTTPS, тільки на одну вшиту адресу;
* файл відкидається, якщо його **SHA-256** не збігається з тим, що в каталозі;
* нічого не завантажується без натискання кнопки.

Перевірено обома боками: правильний файл встановлюється й вантажиться, а з
навмисно зіпсованим хешем у каталозі — «Не збігається контрольна сума», файл
не зберігається й не завантажується.

Хеші рахує `plugins/publish.ps1` із тих файлів, які й публікує. Хеш, вписаний
руками, — це не перевірка.

**Вручну.** Покласти DLL у `plugins` поруч із exe або в
`%APPDATA%\PicoView\plugins` і перезапустити.

## Що вміє додаток

| Можливість | Прапорець | Що робить |
|---|---|---|
| Декодування | `PV_CAP_DECODE` | відкриває формати, яких PicoView не знає |
| Покращення | `PV_CAP_ENHANCE` | збільшує або підвищує якість відкритого зображення |
| Служба | `PV_CAP_SERVICE` | працює у фоні, поки ввімкнений |

Один додаток може вміти будь-яку комбінацію.

Служба — це третій рід додатка. Декодер відповідає, коли його спитають, фільтр
теж, а служба живе стільки, скільки ввімкнена. `service_start` викликається з
потоку інтерфейсу — саме того, хто володіє вікном, — незалежно від того, на
якому потоці додаток завантажився. Своє вікно чи свій цикл повідомлень робіть
у власному потоці й не блокуйте виклик.

Декодер викликається **останнім** — тільки після того, як WIC і вбудовані
запасні декодери відмовилися. Тому додаток не може випадково «перехопити»
JPEG: він отримує лише те, що більше нікому не по зубах. Його розширення
додаються до списку підтримуваних, тож такі файли видно в сітці папки й у
діалозі відкриття.

Покращення викликається вручну — `Ctrl+U` або пункт «Покращити зображення» в
меню «…». Воно міняє лише те, що на екрані; файл на диску не чіпається.

## Куди класти

```
PicoView.exe
plugins\
    upscale.dll
```

або `%APPDATA%\PicoView\plugins\`. Обидві теки переглядаються, тека поруч з
exe має пріоритет за однакових імен файлів.

Список знайдених додатків — у «Налаштування → Додатки». Там же їх можна
вимикати: вимкнений DLL вивантажується одразу, а його ім'я лягає в ключ
`PluginsOff` файлу `PicoView.ini`. Нові формати з'являються та зникають після
перезапуску, бо список розширень збирається один раз на старті.

## Як написати

Потрібен один заголовок — [`include/picoview_plugin.h`](../include/picoview_plugin.h).
Це чистий C без жодних залежностей, тож додаток можна зібрати будь-яким
компілятором: MSVC, clang, MinGW.

Єдиний обов'язковий експорт:

```c
__declspec(dllexport) int PicoViewPluginInit(const PvHost* host, PvPlugin* out);
```

PicoView викликає його один раз, додаток заповнює `out` покажчиками на свої
функції — і далі вони спілкуються тільки через структури з заголовка.

Мінімальний додаток, який вміє збільшувати вдвічі:

```c
#include "picoview_plugin.h"

static int enhance(const PvImage* in, int scale, PvImage* out) {
    if (scale != 2) return PV_ERR_UNSUPPORTED;
    /* ... заповнити out->pixels (BGRA, premultiplied) ... */
    return PV_OK;
}
static void free_image(PvImage* img) { free(img->pixels); img->pixels = 0; }

__declspec(dllexport) int PicoViewPluginInit(const PvHost* host, PvPlugin* out) {
    if (host->abi != PV_ABI_VERSION) return PV_ERR_UNSUPPORTED;
    out->size = sizeof(*out);
    out->caps = PV_CAP_ENHANCE;
    out->name = L"Мій апскейлер";
    out->enhance = enhance;
    out->free_image = free_image;
    return PV_OK;
}
```

### Правила, які варто прочитати до того, як щось не запрацює

**Пікселі.** `PV_BGRA8` — вісім біт на канал у порядку B, G, R, A, **альфа
попередньо помножена**, рядки через `stride` байтів, перший рядок зверху. Це
формат Direct2D, тому нічого дорогою не перетворюється. Фільтр, який дає
канал більший за альфу, побачите як світлу облямівку.

**Потоки.** `decode` викликається з робочих потоків декодера, `enhance` — з
потоку інтерфейсу. PicoView серіалізує виклики власним м'ютексом, але не
покладайтеся на це: тримайте функції реентерабельними.

**Пам'ять.** Виділяйте через `host->alloc` те, що повертаєте, і звільняйте у
`free_image`. PicoView копіює пікселі собі й одразу кличе `free_image`, тож
жити довго їм не треба.

**Помилки.** `PV_ERR_FORMAT` означає «це не мій файл» і не вважається
помилкою — PicoView просто спитає наступний додаток. Решта кодів пишуться в
`picoview.log` під `PG_DEBUG=1`.

**Падіння.** Кожен виклик через межу обгорнуто в `__try`. Додаток, який
впав, вимикається до кінця сеансу, а програма працює далі. Це не пісочниця:
DLL у процесі може все, що може процес.

## Приклади

**[`plugins/sample/sample.c`](../plugins/sample/sample.c)** — декодер і фільтр
в одному: читає `.pcx` (формат, якого не знають ні WIC, ні stb_image) і
збільшує зображення вдвічі фільтром Catmull-Rom із легким unsharp mask.
Заміряно: 200×150 → 400×300 за 4–7 мс. Саме сюди ліг би обгортка над DLSS, NIS
чи моделлю ONNX — інтерфейс той самий, міняється лише те, що всередині
`enhance`.

**[`plugins/hoverpeek/hoverpeek.cpp`](../plugins/hoverpeek/hoverpeek.cpp)** —
служба: наводите на файл у Провіднику, зʼявляється картка з ним. Показує, як
робиться фоновий додаток із власним вікном, і заразом як діставати з Провідника
те, на що ви дивитеся:

1. де курсор і чи зупинився — `GetCursorPos`, безкоштовно;
2. чи це вікно Провідника — `GetClassName`, безкоштовно;
3. який елемент під ним — `IUIAutomation::ElementFromPoint`, десятки мілісекунд, тому тільки після того, як курсор завмер;
4. який це файл — Провідник дає **назву**, а не шлях, і ховає розширення; тека береться з `IShellWindows`, а розширення — одним `FindFirstFile` по `назва.*`;
5. чи є справжня мініатюра — `SIIGBF_THUMBNAILONLY`. Немає мініатюри — немає картки: краще нічого, ніж картка з типовою іконкою.

Картка — шарове вікно, намальоване вручну в DIB: заокруглене, темне, ніколи не
забирає фокус.
